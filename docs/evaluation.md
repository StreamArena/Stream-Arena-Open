# Evaluation protocol

This document follows **StreamEval: Evaluating Interactive Streaming Video Generation Models**, Section 3
(System Evaluation). The machine-readable rules are [evaluation_v2.json](../evaluation/protocol/evaluation_v2.json)
and [scoring_v2.json](../evaluation/protocol/scoring_v2.json); the wire format and run folders are in
[protocol.md](protocol.md).

## Equal treatment

**MUST** and **MUST NOT** state requirements for every participating system.

1. Every system in a task and population uses the same roster, metric applicability, repetition count, judge
   configuration, failure accounting and aggregation. Model identity MUST NOT alter scoring rules.
2. Only the trusted scheduler sees the complete timeline. Inputs are released incrementally after readiness and
   their actual release times are recorded on an evaluator-side monotonic clock. Future inputs and oracles MUST NOT
   reach the model.
3. Every required control stays in the denominator, including unsupported operations and events beyond a session
   limit. Missing required output scores zero; missing judgments remain unresolved and contribute zero to the
   displayed lower bound. Unfired conditional triggers remain in the opportunity ledger.
4. The complete system configuration is registered and input conversions are declared before execution.
   Conversion, upload and processing after an input's timing origin count towards its response delay.
5. Task prompts and evidence processing are shared; there is no model-specific score substitution, prompt amendment
   or output mask.
6. Retries and voided attempts are kept distinct from retained samples (see [Runner settings](#runner-settings)).

## Input conversion and comparison groups

Adapters may resample audio, re-encode media, change image geometry or limit source frame rate, provided they
preserve the released meaning and declare the transformation in `input_adapters` as `native`, `normalized` or
`derived`. The configuration freezes these declarations as `input_contract`.

| Task | Input settings |
|---|---|
| Digital-human dialogue | benchmark portrait or provider-supplied avatar (Identity N/A); † renderer with the shared ASR, dialogue and TTS stack; text-input dialogue is a separate population |
| Avatar performance | supplied audio, or text-derived line and action inputs |
| World generation | text-controlled or image-conditioned inputs; Reference applies to image-conditioned inputs |
| Instruction editing | Vidu S2 Editing receives references generated by qwen-image from the instruction and a fixed product-photo prompt |
| Reference editing | reference A is preloaded; later reference changes arrive online |

Multiple reference slots, removal and restoration are evaluated regardless of interface limitations; restoration is
compared with the source at the corresponding time. Declared routes explain inputs but do not make them
equivalent: definitive comparisons require matched input routes, judge configurations and observation endpoints.

## Metrics

The paper organizes ten metrics into four dimensions: task execution (Dialogue, Following, Edit Success),
state consistency (Stability, Continuity, Preservation), visual fidelity (Quality, Identity, Reference), and
audiovisual coordination (A–V Sync). All use a 0–100 scale; required opportunities remain in their denominators.

| Task | Content metrics |
|---|---|
| Digital-human dialogue | Quality, A–V Sync, Stability, Dialogue, Identity |
| Avatar performance | Quality, A–V Sync, Stability, Following, Identity |
| World generation | Quality, Stability, Following, Continuity; Reference for image-conditioned inputs |
| Instruction editing | Quality, Stability, Following, Edit Success, Preservation |
| Reference editing | Quality, Stability, Reference, Edit Success, Preservation |

| Metric | Definition |
|---|---|
| Quality | Five-second clips rated 5–1 for no defect, one minor, several minor, one severe, several severe defects; rating r maps to 25(r−1). |
| Stability | Share of planned duration covered by clips with no severe temporal defect, at most one minor temporal defect and Quality rating ≥ 3. Authorized edits and cuts are not defects. |
| Identity | Lower of two portrait-comparison ratings against the initialization portrait, or the opening frame for a provider-supplied avatar, mapped by 25(r−1); authorized changes are allowed. |
| Dialogue | Share of planned turns meeting expected content, restrictions, conversational behaviour (waiting, backchannels, interruptions) and response windows. |
| Following | Share of control events performing the requested operation on its target. In performance, supplied speech is not a visual-control opportunity. |
| Edit Success | Share of edit events jointly meeting target, scope, active state, deadline, stable effect and protected-content requirements. Late effects fail. |
| Preservation | Share of checkpoints preserving all declared non-target content and current source motion. |
| Reference | Ratings of declared appearance attributes at active-reference checkpoints, mapped by 25(r−1). |
| Continuity | Share of planned duration meeting motion and camera probes: paths, object permanence, transitions, spatial relations and expected motion. |
| A–V Sync | Share of required speech events with lip–audio correlation r ≥ 0.3 at the pooled system offset whose 95% interval lies within ±200 ms. |

**Overall** is the equal-weight mean of the applicable content metrics. Portrait-conditioned dialogue,
fixed-avatar dialogue, performance and both editing tasks use five metrics.
Text-conditioned world generation uses four. The paper presents all rows alphabetically within each task.
Overall values with different metric sets are interpreted within their respective input settings.

Worked example (illustrative): two five-second clips with one minor defect and none score 75 and 100, so Quality is
87.5. If only the second clip passes the temporal check, Stability is 50. Two controls, one passed and one
unresolved, give Following bounds [50, 100]; the displayed value is 50.

### Response time (local diagnostics)

`delay = first observed correct response − actual input origin`. The origin is the end of published user speech
for audio dialogue and the actual release otherwise. The endpoint is the start of a sustained voiced response that
passes the semantic check, or the first stable correct visual effect. Browser endpoints observe playback after
decoding; in-process endpoints observe decoded-frame callbacks. Physical device delay is excluded, so endpoints
of different interfaces are not matched.

These quantities are retained locally and are not included in the published paper tables.

**P50** is the median delay of correct responses with observed timestamps. **Coverage** is their count divided by
all eligible opportunities, including failures, unresolved events and jobs without measurements. `n.e.` means no
correct response has an observed timestamp; it never means zero delay. An all-opportunity percentile requires enough observed endpoints to identify it; otherwise retain an unresolved status.

## Aggregation and display

Units are averaged within runs, then over **three repeats**, over conditions within each duration stratum, and over
the **five equally weighted strata of 15, 30, 60, 120 and 300 s**. Inapplicable metrics are excluded and shown as
N/A. Unresolved units contribute zero under the same rule for every system, so the displayed value is a lower
bound, rounded down to two decimals; it is neither a complete estimate nor a confidence interval.

Evaluation uses the complete roster in `benchmark/v1/full`.
Every condition remains in the evaluation roster. The expected outcomes and timing requirements are defined
in each roster’s `oracles.jsonl`.

Local sampling-uncertainty diagnostics keep related conditions and repeats together. Their numerical
intervals are not part of the maintained publication. Rows are alphabetical; no significance ranking is assigned.

Run a population with `--benchmark <folder> --population <population>`; its frozen preparation is the aggregation
roster.

## Automated judge

Visual judges return structured defect observations, and fixed rules derive ratings and decisions. Clips are
sampled at 0.5, 1.5, 2.5, 3.5 and 4.5 s of each five-second window. Identity gives two judges the same portrait and
frames and keeps the lower rating; the defaults are `qwen3.8-max-0902` and `qwen3-vl-plus`. Dialogue is checked on
transcribed output speech. Editing checks the active target state and protected content against source frames at
the corresponding source time. Following uses each event's own window. Prompts and rules are in
`streameval/judge/prompts.py`; evidence selection is in `streameval/judge/units.py`. Configuration identifiers
and prompt hashes bind reusable measurements.

### A–V Sync

[av_sync_rule_v2.json](../evaluation/protocol/av_sync_rule_v2.json) specifies speech detection, lip-opening
observations, the pooled offset and the correlation. Missing required speech fails; sparse or ambiguous evidence
stays unresolved. A–V Sync is provisional.

### Measurement validity

Calibration requires false-pass ≤ 5%, false-fail ≤ 10% and unresolved ≤ 10% per validation class.
The runtime declares `streameval.structured-judge/5`, `/5-ext/1` and A–V Sync version 2.
Validate the exact models, prompts, sampling and rules independently before making ranking claims.
Historical calibration results are not bundled. Without matching validation evidence, the scorer keeps
the affected metrics provisional; software smoke tests do not establish measurement validity.

## Runner settings

The runner uses a 180-second readiness timeout and up to three retries before the session epoch. It keeps the
first started attempt: a refusal of a released input, an early end or a delivery error is not replaced by a later
success, and missing final evidence remains unresolved. The paper does not specify these numerical values. Other
repetition counts are allowed for diagnostics only. Cache identity covers evidence, preparation, policy, prompts
and judge models; failed judge requests remain unresolved and give a nonzero exit status.

Evaluation results, calibration records, requests, endpoints, accounts, host details and execution logs
stay local ([reproduce.md](reproduce.md)). The release provides executable scoring rules and benchmark
definitions without maintained evaluation scores or result tables.
